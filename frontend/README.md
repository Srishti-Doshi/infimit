# Infimit Frontend

React SPA — public reader experience, author/editor dashboards, admin tools. Vite, TypeScript (strict), TailwindCSS, React Router v6, TanStack Query, Zustand, MSW.

This is the Subphase 1 scaffold. See [`docs/Phase_1/Subphase_1_Foundations/Frontend_Handler_Documentation.md`](../docs/Phase_1/Subphase_1_Foundations/Frontend_Handler_Documentation.md) for scope and exit criteria.

## Quick start (local)

```bash
# 1. Install deps
npm install

# 2. (Optional) copy env template — defaults already enable MSW mocking
cp .env.example .env

# 3. Run the SPA in watch mode with MSW intercepting every endpoint
npm run dev
```

The SPA listens on `http://localhost:5173`. By default `VITE_USE_MOCK=true` so no backend is required — MSW serves fixture data for every documented endpoint.

To call the real backend, set `VITE_USE_MOCK=false` in `.env` and have the backend running on `http://localhost:4000` (per the backend README).

## Running with Docker (full compose)

```bash
docker compose -f ../docker-compose.dev.yml up --build frontend
```

This builds the production bundle (Vite → nginx) and serves it on `http://localhost:5173`. Production builds **do not** include MSW — the bundle is stripped of all mock code via Vite's tree-shaking.

For the full stack (mongo + redis + backend + frontend):

```bash
docker compose -f ../docker-compose.dev.yml up --build
```

## Architecture & conventions

- **No business logic in components**: components render, hooks orchestrate, `lib/` talks to the API. Same rule we use on the backend.
- **No `dangerouslySetInnerHTML` anywhere yet**. When article body rendering lands in Subphase 5, it must go through DOMPurify per [`docs/10-security.md`](../docs/10-security.md) §10.1.
- **Tailwind utility-first, but build reusable primitives**. Don't paste utility soups across pages — extend the primitives in `components/ui/` instead.
- **No raw hex colors** outside `src/styles/tailwind.css` and `tailwind.config.ts`. Every UI value flows through a token. See [docs/design-tokens.md](docs/design-tokens.md).
- **Strict TypeScript** — `noUncheckedIndexedAccess`, `noUnusedLocals`, `noUnusedParameters`. Don't relax later; it gets harder.
- **Accessibility from day 1**: semantic landmarks (`<header>`, `<main>`, `<nav>`, `<footer>`), focus rings preserved, color contrast ≥ AA. WelcomeSplash + Modal use Radix Dialog so focus-trap, escape, scroll-lock, and ARIA are handled correctly.
- **Mobile-first responsive**: every component built mobile, enhanced for larger viewports. Header collapses to hamburger drawer below `lg`.

## Design language

See [docs/design-tokens.md](docs/design-tokens.md) for the full token spec.

Quick summary:

- **Display font**: Fraunces (variable serif) — wordmark, headlines
- **Body font**: Inter (variable sans) — UI, body, labels
- **Brand accent**: `#DC2626` (token: `brand-red-500`)
- **Ink hierarchy**: primary `#0F0F10` / secondary `#4B5563` / tertiary `#9CA3AF`
- **Surfaces**: white default, `#F9FAFB` subtle, `#FFF1F2` rose-tint, `#EFF6FF` blue-tint
- **Spacing scale**: Tailwind default (4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96 px)
- **Radius**: 4 / 6 / 8 / 12 / 16 px — pills reserved for status indicators and dark splashes

Tokens are CSS variables (raw `R G B` triples) wired through Tailwind. Dark mode in Phase 2 is a single variable-swap away — no component code changes needed.

## State & data flow

- **Server state**: TanStack Query (`useQuery`, `useMutation`). One QueryClient at root. `staleTime: 30s`, `gcTime: 5m`, `refetchOnWindowFocus: false`.
- **UI state**: Zustand. One slice per concern — `useUIStore` (overlay open/close), `usePreferencesStore` (persisted user preferences). No Redux.
- **Forms**: React Hook Form + Zod resolver (planned for Subphase 2 forms; the primitive Input is already RHF-friendly).
- **HTTP**: axios with `withCredentials: true`. Single shared `apiClient` from `lib/api-client.ts`. Request/response interceptors centralize auth-token injection (Subphase 2) and error envelope transformation.

## MSW mocking

Mock Service Worker intercepts the network in dev. Every endpoint from [`docs/05-api-documentation.md`](../docs/05-api-documentation.md) has a handler at `src/mocks/handlers.ts`. Fixtures live in `src/mocks/fixtures.ts`.

- Default behavior in `npm run dev`: MSW active, every endpoint returns `{ success: true, data: <fixture> }`.
- Disable: set `VITE_USE_MOCK=false` in `.env`.
- Override per test: pass extra handlers to `worker.use(...)` in Vitest setup.

## Known caveats (worth tracking, deferred)

| Item                                                                                        | Severity                       | Plan                                                                             |
| ------------------------------------------------------------------------------------------- | ------------------------------ | -------------------------------------------------------------------------------- |
| `@typescript-eslint` plugin doesn't officially support TS 5.9 (installed via `^5.6.3`)      | Cosmetic warning only          | Bump plugin when v8 + ESLint 9 are both stable. Defer.                           |
| ESLint 8 is end-of-life (security patches only)                                             | Cosmetic warning               | Migrate to ESLint 9 + flat config in a dedicated PR. Defer.                      |
| Lucide brand icons (`Facebook`, `Twitter`, `Linkedin`) deprecated due to trademark concerns | Hint only — icons still render | Swap to `simple-icons` or inline SVGs when the icons start emitting hard errors. |
| Reduced-motion users see a static ticker                                                    | By design (WCAG 2.3.3)         | Document; don't fix.                                                             |
| Docker `actions/cache@v4` uses Node 20 runtime (deprecated by GitHub)                       | Cosmetic                       | Bump when v5 lands.                                                              |
